## 一、杀伤链能力矩阵（现状审计）

按经典杀伤链逐阶段盘点（工具=hosttools 宿主工具，agent=平台领域工具，
skill=方法论包）：

| 杀伤链阶段 | 已有能力 | 缺口（本轮已补标注 ✅新增） |
|---|---|---|
| 侦察 Recon | nmap/masscan/httpx/subfinder/dnsx/katana/whatweb + api-recon skill + 资产图 | 够用 |
| 武器化 Weaponization | search_vulns/get_poc（NVD+KEV+GHSA+PoC）/scan_with_nuclei + nuclei 模板库 | 够用（情报层是独有优势） |
| 初始访问 Initial Access | sqlmap/dalfox/hydra/弱口令 + vuln-hunting 七维度 + 漏洞验证闭环 | 够用 |
| **执行与落地 Execution** | Bash/nc/ssh + **回连接收器 listener_start/sessions ✅新增**（接住反弹 shell/OOB 并留证） | ✅ 补齐（此前的 stub 已删） |
| **权限提升 PrivEsc** | linpeas ✅新增 / pspy ✅新增 / search_vulns 内核 CVE | ✅ 基本补齐（GTFOBins 数据库引用进 skill） |

| **横向移动 Lateral** | netexec/evil-winrm ✅新增/impacket/ssh + chisel/ligolo-ng ✅新增/sshuttle ✅新增/proxychains4 ✅新增 + net_context（回连地址） | ✅ 补齐主力件 |
| **数据获取 Collection** | find/tar 类 Bash 命令 + workspace | 方法论指引进 skill ✅ |
| **数据回传 Exfiltration** | MITM 代理全留痕 + notify（OOB）+ listener ✅ + C2 出口配置 ✅新增（direct/ssh 中继/manual） | ✅ 补齐 |
| C2/会话管理 | listener 会话记录 ✅ | **刻意不做交互式 C2**（见下） |

结论：这轮补齐后，杀伤链**全阶段都有平台级支撑**。剩余短板是「深度」而非
「有无」——由 skill 方法论与实战迭代解决。

## 二、C2 出口架构（本轮新增，可选功能）

红队回连的第一道现实问题：**目标该连哪**。三种网络形态：

| 形态 | 配置 | 行为 |
|---|---|---|
| 本机有公网 / 与目标同内网 | `mode=direct`（默认，零配置） | LHOST 自动取本机网卡地址（默认路由源地址或指定网卡） |
| 本机无公网 + 公网中转机（托管隧道） | `mode=ssh` + `c2_relay_ssh=user@host:22`（+密码或私钥路径） | 平台自动建 SSH 反向隧道（`ssh -R 中转同号端口→本机监听端口`），断线指数退避重连，监听器停止自动拆除；LHOST=中转机公网地址 |
| 本机无公网 + 已手工配转发 | `mode=manual` + `c2_relay_host=<中转公网地址>` | 平台只负责在回连信息里展示中转地址 |

- 配置入口：系统设置 API `GET/PUT /api/c2/config`（密码脱敏回显）。
- **对 agent 透明**：`listener_start` 返回 `connect_back={lhost,lport,via}`——
  payload 里的回连地址**以此为准**，agent 不需要自己判断网络形态。
- 端口 1:1 映射（中转端口=本机监听端口）：规则简单，人工排查不用对表。
- 全部可选：不配置=direct，行为与旧版一致。

**安全边界**：监听端口限 1024-65535（绑低端口需特权，走 hostd 或外部转发）；
启停走拦截规则 ask（人工确认）；会话捕获上限 64KB/会话（防灌爆）；
交互式 shell 不做（用 Bash nc/socat——**不自建 C2 框架**，Sliver/Mythic 是
集成对象）。

   agent 工具 `listener_start/stop/sessions`、ask 规则恢复（匹配真实工具）、

   pspy/linpeas（peass-ng，资产名实测）——9 个后渗透主力件。
