## 二、审计发现但未做的（按价值排序）

### A. 该实现的（设计了没跑起来的）

| # | 项 | 现状 | 建议 |
|---|---|---|---|
| A1 | **回连接收器（listener）** | 已删除占位 stub | 反弹 shell 回连是渗透平台的真实需求，但值得**正式设计**而不是 52 行 stub：监听端口/协议（TCP/SMB/LDAP）、按任务归属会话、与防火墙/Docker 端口映射的关系、会话交互 UI。做之前先把拦截规则与审批流设计好（这正是原 ask 规则想管的事）。排在 G 系列之后 |
| A2 | **GHSA CWE 已落库但 skill 联动只在工具输出里** | v0.3.84 做了 `related_skills` 注入，但 planner 提示词没提这个字段 | 在 worker/planner 提示词里加一句「search_vulns/get_vuln 返回 related_skills 时先加载对应 skill 再深挖」——一句话成本，打通最后一厘米 |

### B. 该优化的（有实现但体验/效率有毛刺）

| # | 项 | 现状 | 建议 |
|---|---|---|---|
| B1 | **装机代理必填体验** | 国内机器不配代理时 apt 能装、GitHub 类工具全失败，失败信息在任务日志里 | hostenvInstall 对 github 类工具且代理为空时，前置提醒「未配置装机代理，GitHub 下载大概率失败」 |
| B2 | **批量安装失败重试** | 本轮装齐后失败项只能再点一轮 | 装齐结果 toast 里给「重试失败项」按钮（数据都在 skipped/failed 里） |
| B3 | **体检页只显示版本有无** | `available=true` 但版本过旧（如 nuclei 模板半年没更）看不出来 | Tool DTO 加 `version` 字段，体检页显示；模板树已有时显示 last commit 日期 |
| B4 | **任务模板的拦截规则无预览** | 选模板后 rules 直接生效，看不到会拦什么 | 模板选择处展示规则摘要 |
| B5 | **通知渠道无测试按钮状态记忆** | 测试发送成功/失败不落历史 | 已有 deliveries 历史，补「最近一次测试结果」列 |
| B6 | **hostd 入队不去重** | Kali 实测：批量接口意外触发两次，同一工具 52 个任务重复入队（apt/pip 幂等无害但耗时翻倍） | Start() 时查同 tool_id 的 queued/running 任务，命中直接返回已有 job |

### C. 该删的（冗余）

| # | 项 | 理由 |
|---|---|---|
| C1 | `intercept_enabled_tools` 里已部署实例残留的 `listener_*` | 工具不存在，白名单项是死配置。**不动**（改用户持久化数据违反迁移纪律），仅记录 |
| C2 | server 包两个 flaky 测试（ChatMention 时序 / TempDir 竞态） | 全量跑偶发红，每次都要人工复核。值得各花半小时做时序加固（deadline 放宽/临时目录重试），消掉持续的心智税 |

## 三、PM 视角：新功能建议（按「平台已有数据/能力」的边际成本排序）

| # | 功能 | 为什么值 | 边际成本 |
|---|---|---|---|
| P1 | **单位发现成本视图** | llm_usage 按 intent 聚合已有全量数据，只缺一张「每个 finding 花了多少 token/钱」的报表。是向老板/客户证明平台价值的最直观指标 | 低 |
| P2 | **Finding 复测报告进 Word 导出** | 复测闭环（v0.3.83 前已有）的历次结论只在线上可看；客户交付要 Word。数据全在 finding_retests | 低 |
| P3 | **资产 auth 字段的过期提醒** | `auth_request` 依赖资产上登记的凭据；凭据改密后 agent 反复失败浪费轮次。按最近失败次数给 auth 数据打「疑似失效」标 | 低 |
| P4 | **任务复盘页（timeline）** | 双图数据齐全，缺一张「时间 × 意图/事实/发现」的紧凑时间线，让「这次任务干了什么、卡在哪」一眼看完 | 中 |
| P5 | **拦截规则命中统计** | 拦截历史数据都在，缺按规则聚合的命中数——用户该知道哪条规则天天在拦（该收紧/该放行） | 低 |
| P6 | **M 清单第二批**（能力对比文档 §五） | 三态收口（M11）仍是可信度最大短板；LLM 循环检测（M4）治「有写回但在原地打转」 | 中-高 |

## 四、刻意不做的（记录决策）

- **重新实现 listener**：见 A1——值得做，但要做对（正式设计），不做半成品。
- **清理已部署实例的 `listener_*` 白名单残留**：改用户持久化数据违反迁移纪律。
- **前端 lint 进 CI**：75 个存量 error 是行为级修复（空 catch/await），值得独立专项而不是顺手改（改动面大、回归风险高）。
