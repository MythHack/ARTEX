## 3. 发现的问题清单（该修的都在这）

### P1 · CHANGELOG 断档（文档债，最显眼的问题）
`CHANGELOG.md` 最后一条是 **0.3.62（2026-10-21）**，而 tag 已打到 **v0.3.83**——中间 21 个版本（含拦截规则整改、部署加固、挖掘能力批次、手机端适配四个重要批次）没有更新日志。交接文档覆盖了这些内容，但 CHANGELOG 是对外（Release 页）可见的变更记录。**建议**：补一批按批次的概括性条目（不必逐版本），并约定"打 tag 必须带 CHANGELOG 条目"。

### P2 · ratelimit.go 注释与行为不符（小 bug）
`vulnintel/ratelimit.go:63-65` 注释说"若中途换了 key，下一轮同步时重建即可"，但实现是 `sync.Once`——**进程内限速间隔按第一次使用的 key 固定，换 key 后不会重建**，直到重启服务。影响：先无 key 跑过（6.5s 间隔）再在 UI 配置 key 的实例，同步仍按匿名速率跑（慢 9 倍但不出错）。**建议**：把 Once 改为按 key 值变化重建（10 行内的改动）。

### P3 · `isRecentCritical` 死参数（代码卫生）
`vulnintel/nvd.go:205` 的 `severity` 参数未使用（实际判据是 score≥9.0 或 KEV，行为正确且与 `fastlane.go:91` 的 `selectRecentCritical` 语义一致）。**建议**：删掉死参数或让两处共用同一个函数。

### P4 · evidence 目录 fsync 的 Windows 可移植性（继承问题，记录在案）
`evidence/store.go:115` `d.Sync()` 在 Windows 必然失败 → 证据子系统在 Windows 主机上不可用。项目发 windows/amd64 包且带 `start.bat`，但 CI 只测 Linux，这个缺口不可见。**建议**：二选一——① `runtime.GOOS == "windows"` 时跳过目录 fsync（10 行内）；② 在 README/部署手册明确"证据子系统仅支持 Linux 部署"。

### P5 · 提交信息与内容不符的一例（流程，非代码）
commit `afdebc0` 标题是"remove incomplete listener feature"，实际 diff 是**重建**了 52 行的 `listener/listener.go` 最小包（移除的是不完整的 agent 集成）。不影响行为，但误导追溯。**建议**：无需改历史，知晓即可。

### P6 · 文档微滞后两处
① 代理池写"三策略"实际四种（`sticky_host_random` 是后来加的）；② playwright-cli/scopesentry 两个 helper 类 skill 只有 class 标签没有 cwe/attack（合理设计，但标签覆盖统计时要知道）。

## 4. 问题 (a)：功能价值分级

### 好——保持并继续投入（按价值排序）

1. **vulnintel 情报层**（批次 2/3/6 的核心）：「按时间流的持续情报运营」（快通道 30 分钟一轮、CVSS≥9 或 KEV）在同类产品调研中是**独一份的领先项**；实现质量高——页级游标续跑、共享限速闸门、版本待定"两源合并"判定、倒排索引（修过 28 秒/3.3 万行日志的性能事故）、KEV stub 行。仿真实测 KEV 全量同步成功。
2. **拦截规则整改**（批次 5）：「不可逆性 × 作用对象」三层判据清晰且与裁决提示词对齐；规则级 timeout 死字段修通全链路；迁移指纹保护用户改动；每条规则的 rationale 让分类可审计。这是平台安全性与可用性的关键平衡点，整改方向完全正确。
3. **LLM 稳定性家族修复**（批次 4 + 散点）：Compactor 自死锁（SIGQUIT 栈定位根因，还点破了"15 分钟墙钟对自死锁无效"）、planner 墙钟+独立 goroutine 双保险、thinking 降级换 provider（修掉了上一版条件恒为假的死代码）、budget 调优。**本次仿真中 429 限流的"提交前安全窗口重试"和"意图级 model_error 重跑（2/2）"实景触发并按设计工作**——这一族修复直接决定了平台在真实（不稳定）LLM 通道上能不能跑。
4. **挖掘能力批次**（auth_request / diff_responses / api_contract / GHSA / skill 标签）：精准补掉 G2/G5 缺口（能力对比文档确认"资产里有 auth 数据却只能当文本读"的浪费）；双实现对照测试、真 shell 转义测试是同类工具里少见的严谨。
5. **证据链修复**（v0.3.62）：流量引用改"尽力而为"（修掉"猜错一个 ID 丢掉已确认漏洞"的净损失缺陷）、重复上报也绑流量——修的都是开关打开后立刻会踩的坑。
6. **部署链加固**（批次 6）：SHA256 强制、角色密码同步、崩溃循环上限、ETXTBSY 处理——每一条对应一个真实事故（交接文档与部署手册可交叉印证），部署可靠性显著提升。
7. **结构性去风险**（批次 1）：norma fork、CI 门禁、文档重建——在"原作者已删库"的背景下，这三件事是整个接手能够持续的前提。

1. **单通道免费 LLM 跑任务会被限流卡住**（仿真实证：glm-4.7-flash 免费档 429 频繁，单意图最终 blocked）。这不是平台缺陷——平台的重试/收场行为全部正确——但**实战部署必须配多通道 + LLM 轮询**（文档已知，值得强调为部署前置条件）。
