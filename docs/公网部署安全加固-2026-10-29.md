# 公网部署安全加固说明

> 2026-10-29（v0.3.85）。本文记录面向公网部署做的安全加固内容、部署方必须
> 配合的事项，以及已知的边界。

## 一、本轮加固了什么

| 项 | 内容 |
|---|---|
| 登录防爆破 | `/api/auth/login` 与 `/api/auth/init`：每 IP 10 分钟内失败 5 次 → 锁 15 分钟；全局 1 分钟 30 次失败 → 全局锁 5 分钟（兜底 XFF 伪造）；失败响应固定延迟 300ms 并记录来源 IP |
| 探活端点去指纹 | `/api/health` 只回 `{"ok":true,"status":"ok"}`——不再暴露 service 名与精确版本号（公网测绘最省事的 body 指纹）。版本查询走**鉴权的** `/api/version` |
| 改密码吊销会话 | 改密码成功即**轮换 JWT 签名 key**，全部旧 token 立即失效（此前泄露的 token 能用到 7 天自然过期） |
| 安全响应头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`；`/api/*` 一律 `Cache-Control: no-store` |
| 移除 CORS 放行 | 前端与 API 同源部署，`Access-Control-Allow-Origin:*` 只有放宽跨站读取一个效果，已整体移除 |
| 认证面去产品名指纹 | 登录页/初始化页整体重做（居中单卡片、内联几何标记替代图片 logo、中性文案）；根路径 / 404 / 登录 / 初始化的文档标题改为「Console」；favicon 换为无可识别图案的中性图标。导出产物已验证：未鉴权可达页面 0 处产品名 |

**设计边界（刻意不做）**：登录后界面（已过鉴权）内的产品名、侧边栏 logo 保持不变——可见它们的前提是已经通过认证，不构成未鉴权指纹。

## 二、部署方必须配合的事项

1. **反代必须覆写 `X-Forwarded-For`**（`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`）。登录限流按该头计数：不覆写的话，客户端可伪造此头绕过按 IP 锁定（全局阈值仍在兜底，但按 IP 维度会失效）。README 的 nginx 示例已包含。
2. **必须走 HTTPS**（nginx TLS 终结即可）。JWT 通过 `Authorization` 头与 `artex_token` cookie 传输，明文 HTTP 上等于裸奔。
3. **强密码**：密码是公网部署唯一的认证边界（本系统可在服务器上执行命令）。最少 8 位是下限而非建议值。
4. **不建议在公网实例上配置真实目标的授权凭据**（资产 `auth` 字段）除非你接受该风险——拿到平台访问权的人能通过 `auth_request` 读到它们。

## 三、已知边界

- 限流是进程内存态：服务重启清零（影响的是攻击者的等待时间，不影响正确性）。
- 全局阈值能兜住 XFF 伪造，但分布式低速爆破（大量 IP 各打 4 次）在原理上无法被单机限流根治——公网实例建议额外套一层 WAF/CDN 限速。
- 未鉴权可达面：`/api/auth/*`（status/init/login/change-password——change 自带 token 校验）、`/api/health`（已泛化）。已逐一路由核对，无其他豁免。
